# iSpring: тестовое задание аналитика, задача 1 — схема БД и отчёт по продажам

Исходное задание: https://github.com/ispringtech/coding-interview/blob/master/analyst/README.md (пункт 1:
«Построить небольшую схему БД и запрос для отчёта по продажам»).

## Что сделано
- Схема реляционной БД онлайн-магазина: группы товаров, товары (в том числе без группы), история цен,
  клиенты, заказы со статусом, позиции заказов — `docs/schema.md` (диаграмма) и `sql/01_schema.sql`.
- SQL-запрос: количество заказов, штук и сумма продаж по месяцам, товарным группам и товарам — `sql/03_report.sql`.
- Тестовые данные (`sql/02_seed.sql`) и автоматические проверки (`tests/`, GitHub Actions).

## Что не сделано
- Пункты 2 и 3 задания (статистический анализ выборки клиентов и визуализация результата): нужны csv-файлы
  и статистика на Python, это отдельная большая работа, а на задание было 6–8 часов.

## Как запустить (PostgreSQL 14+)
```bash
createdb shop
psql -d shop -f sql/01_schema.sql   # таблицы
psql -d shop -f sql/02_seed.sql     # тестовые данные
psql -d shop -f sql/03_report.sql   # отчёт
```

## Как проверяли
```bash
PGDATABASE=shop bash tests/run_tests.sh
```
Скрипт пересоздаёт схему, сравнивает результат отчёта с эталоном `tests/expected_report.csv`
(проверен вручную) и убеждается, что БД отклоняет некорректные данные. Те же проверки идут
в GitHub Actions при каждом push (`.github/workflows/tests.yml`).

Что покрывают тестовые данные: товар без группы; смена цены (старые продажи остаются по старой цене);
заказ на границе месяцев (28.02 23:30 и 01.03 00:00); переход через год; отменённый заказ (не попадает в отчёт).

## Ограничения
- Месяцы без продаж в отчёт не попадают (строк нет, а не нули).
- Отчёт считает по `unit_price` из позиции заказа, скидки и доставка не моделируются.
